## UI-09 — Đăng nhập, đăng ký Customer, xác thực OTP, quên hoặc đặt lại mật khẩu cho đúng luồng của hai ứng dụng

**Phụ trách:** Trần Nguyễn Hữu Khánh · **Sprint:** 1 · **Ước lượng:** 5 SP
**Phụ thuộc:** —

### 1. User Story

- **Là Admin**, tôi muốn đăng nhập, đăng ký Customer, xác thực OTP, quên hoặc đặt lại mật khẩu cho đúng luồng của hai ứng dụng để quản lý dữ liệu và thao tác nghiệp vụ đúng quyền.

### 2. Công việc

- Đọc trang hiện có, AuthShell/AuthLayout, API DTO và Identity controller. Lập bảng route → field → request → success destination; không viết lại form từ đầu.
- Hoàn thiện validation theo contract thực: email trim, required fields, password/confirm, OTP format; không trim password hoặc tự sáng tạo password policy khác backend.
- Chuẩn hóa pending/error/focus field lỗi; Enter submit đúng form, nút hiện password/resend không gửi nhầm form, thao tác lặp không phát request trùng.
- Rà chuỗi register → verify và forgot → reset: email context phải hợp lệ; refresh/deep-link thiếu context có hướng quay lại nhập, không sinh email giả hoặc lưu password để “gửi lại”.
- Chốt resend với Identity; thay call rỗng bằng contract được duyệt nếu có. Khi chưa có contract, báo rõ phần resend chưa nghiệm thu, không làm success giả.
- Rà React login với cả role hợp lệ và CUSTOMER; không điều hướng dashboard bằng default ADMIN. Phối hợp owner auth integration để thay mock session/guard ở đúng task, không tự sửa backend RBAC trong UI-09.
- Hoàn thiện vi/en, label/autocomplete/focus và responsive; Google component có sẵn vẫn thuộc UI-49, không dùng Google success để bỏ qua AC email/password.
- Bàn giao fixture từng lỗi, payload đã che dữ liệu nhạy cảm và điểm cần INT kiểm chứng cookie/refresh/logout. Không gọi SMTP/API hoặc chạy browser trong lần viết detail.

### 3. Contract và đầu ra

| Flow | Dữ liệu / hành vi cần bàn giao |
| --- | --- |
| Customer register | fullName/email/phone nếu dùng/password theo DTO; confirm-password chỉ để UI đối chiếu, không thêm field tùy ý vào payload; success chuyển verify với email đã chuẩn hóa |
| Verify OTP | email + otp theo contract hiện tại; nhập/paste/backspace thuận tiện, thiếu email/code chưa đủ thì không submit; verified chỉ sau API success |
| Login hai app | email/password; credentials qua Gateway; pending khóa submit; role không thuộc app phải được xử lý rõ, không rơi về mock ADMIN |
| Forgot/reset | Forgot gửi email; reset gửi email/otp/newPassword; thông báo không tiết lộ tài khoản vượt contract; password mismatch/OTP sai hiển thị tại đúng bước |
| Lỗi | Validation tại field, lỗi API qua error-code/i18n adapter; network error có thử lại, giữ input không nhạy cảm; không log password/OTP/token |
| Session | Access token/role/storeId nhận từ response theo contract; refresh cookie do server quản; redirect thành công không thay thế xác minh phiên/quyền |

### 4. Tiêu chí hoàn thành

- Register thiếu field/email sai/password mismatch; sau đó sửa hợp lệ: Lỗi đúng field, không gửi request invalid; success chỉ chuyển verify sau API xác nhận
- OTP thiếu chữ số, paste code hợp lệ, code sai/hết hạn: Nhập/paste dùng được; thiếu code không submit; lỗi server không hiện verified hoặc điều hướng account
- Resend trước/sau cooldown và API trả lỗi: Không gọi register payload rỗng chưa được duyệt; chỉ báo sent khi API thực sự success
- Login hai app với pending/network error/sai mật khẩu: Chặn submit lặp, lỗi rõ, không sinh JWT/demo user hoặc chuyển trang success giả
- CUSTOMER vào Admin; lần lượt STAFF/MANAGER/ADMIN hợp lệ: Không fallback ADMIN; role/scope đi đúng contract và luồng guard được INT xác nhận riêng
- Forgot/reset thiếu email context, password mismatch hoặc OTP sai: Có đường sửa/quay lại; chỉ thông báo reset thành công sau API success, không lộ thông tin ngoài contract
- Keyboard/mobile/vi/en và rà token storage: Label/focus dùng được, text đổi locale; không lưu refresh token/password/OTP hoặc log chúng
- Customer register → nhận/verify OTP → login → reload/refresh → logout, sau đó gọi lại API bằng phiên cũ: Trước logout phiên đúng người; sau logout phiên đã thu hồi không còn truy cập được theo contract; mỗi bước có network và server evidence
- OTP hết hạn/reuse: Không tạo session
- Refresh bị thu hồi: UI về trạng thái xác thực phù hợp
- SMTP lỗi: UI không báo email đã gửi thành công giả
- Role CUSTOMER đăng nhập app Admin và STAFF quán A mở dữ liệu quán B: Không rơi về ADMIN mặc định, không lộ dữ liệu khác scope; backend chặn độc lập với guard
- Hai request gặp access token hết hạn cùng lúc; refresh lỗi: Không có vòng lặp refresh, không success giả; UI về trạng thái auth được chốt
- Submit form hợp lệ với outcome backend đã chốt: UI gửi/chờ/kết quả đúng semantics, success không khẳng định inbox nếu chỉ queued/accepted
- SMTP failure: Không hiển thị đã nhận OTP
- Double submit: Không gửi request lặp không kiểm soát
- Forgot email không tồn tại: Không lộ thêm thông tin trái policy
- SMTP/network lỗi hoặc request lặp trong pending/cooldown: Không báo đã nhận OTP giả, không gửi lặp không kiểm soát và có retry hợp lệ
- Forgot email không tồn tại rồi đổi vi/en: Không lộ thông tin ngoài policy, error/copy đổi locale đúng và không log email/password thừa
- Guest hoàn tất hành trình chuẩn trên tài khoản test và reload: Mỗi chặng có request/data thật, Order/COD đúng owner/store/tổng, không demo fallback
- Luồng chuẩn: Mỗi bước có dữ liệu thực, không localStorage mock thay backend
- OTP sai hoặc món hết tại checkout: Không tạo đơn sai, lỗi đúng bước
- Gửi lại checkout: Không tạo order/payment thứ hai
- OTP invalid hoặc stock đổi sau preview: Bị chặn tại bước đúng, không tạo order sai hoặc session giả
- Retry checkout sau mất response: Cùng order theo idempotency contract, không payment thứ hai
- Bàn giao contract, mã lỗi và kết quả tự kiểm thử kèm commit, môi trường, bằng chứng; ghi rõ lỗi hoặc phần còn bị chặn.

### 5. Điểm cần chốt

- *PIC UI + owner Identity:** resend endpoint/payload, OTP expiry/cooldown, password rules và error codes. Chưa có hợp đồng thì chỉ hoàn thiện giao diện phần độc lập, ghi blocker cho resend.
- *PIC React + owner auth integration:** nguồn session thật và điều hướng theo role/storeId; mock role switch không phải production authorization. Không cho CUSTOMER đăng nhập Admin rồi giữ ADMIN mặc định.
- *PIC UI + Gateway:** cookie/CORS/credentials ở từng môi trường; không đọc HttpOnly cookie bằng JS hoặc nới CORS để che lỗi.
- Error code mới đi qua danh mục nguồn rồi sinh lại, không sửa trực tiếp file generated. Font/brand kế thừa quyết định UI-01/UI-02; không mở rộng thành rebrand.
