## 1. Làm xong task này thì được gì?

Frontend nhận lỗi có cấu trúc và mã ổn định từ Gateway/các service, hiển thị vi/en theo code thay vì exception thô. Người làm API có sẵn ApiException, ApiError, handler và mẫu phân trang, không tự tạo mỗi service một định dạng.

**Đầu ra:** error contract nhất quán, các output generated từ một danh mục, handler đúng luồng servlet/reactive/security và response phân trang rõ ràng. Không tạo Error Service hay Java shared module khiến các app phụ thuộc runtime vào nhau.

## 3. Contract phải bàn giao

### Lỗi HTTP

| Trường | Kiểu/ý nghĩa |
|---|---|
| timestamp | Chuỗi thời điểm ISO-8601 từ Instant, không phải chuỗi giờ local thiếu offset |
| status | HTTP status dạng số, khớp status của response và catalog |
| error | Reason phrase theo status; không dùng để frontend phân nhánh |
| code | Mã ổn định từ contracts/errors.json, ví dụ VALIDATION_ERROR hoặc RESOURCE_CONFLICT |
| message | Thông báo tiếng Anh an toàn trong catalog, không lấy Throwable.message |
| path | Đường dẫn request; không đưa query chứa token/credential vào body lỗi |

Ví dụ lỗi validation, chỉ là contract minh họa, chưa phải response đã gọi thực tế:

```json
{"timestamp":"2026-11-03T10:00:00Z","status":400,"error":"Bad Request","code":"VALIDATION_ERROR","message":"The submitted information is invalid.","path":"/api/auth/register"}
```

### Response thành công và phân trang

Giữ DTO nghiệp vụ hiện có, không tự bọc tất cả response trong envelope success/data mới. Mẫu page đang có là `content`, `page`, `size`, `totalElements`, `totalPages`; content là DTO, không JPA entity. API dùng page bắt đầu từ 0; config chung đặt size mặc định 20 và max 200.

Ví dụ page rỗng tại trang đầu: `content=[]`, `page=0`, `size=20`, `totalElements=0`, `totalPages=0`. Không trả 404 chỉ vì danh sách rỗng. Giá trị page/size âm, sort không hợp lệ phải có quy tắc input thống nhất được chốt ở mục 5, không âm thầm thay contract của endpoint.

### Ánh xạ lỗi tối thiểu

| Đầu vào/nguồn lỗi | Status/code mặc định | Yêu cầu |
|---|---|---|
| DTO validation, JSON hỏng, kiểu tham số sai | 400 / VALIDATION_ERROR | Không trả rejectedValue chứa mật khẩu hoặc raw parser message |
| Chưa xác thực/token sai | 401 / UNAUTHENTICATED | Security layer cũng dùng ApiError; giữ WWW-Authenticate: Bearer |
| Token đúng nhưng thiếu quyền | 403 / FORBIDDEN | Không mô tả dữ liệu bị cấm trong message |
| Resource không tồn tại | 404 / RESOURCE_NOT_FOUND | Không để not-found rơi thành 500 |
| Unique constraint hoặc optimistic lock conflict | 409 / RESOURCE_CONFLICT | Không lộ SQL/constraint detail; mã domain cụ thể chỉ dùng khi có trong catalog |
| Lỗi không dự kiến | 500 / INTERNAL_ERROR | Thông báo chung an toàn, không trả exception/stack trace |

ApiException với mã domain có sẵn dùng status/message của chính mã đó. Giữ những lỗi chuẩn khác đã có như 405/413/415/429, không ép mọi 4xx về 400 hoặc 500.

## 4. Thứ tự thực hiện

1. Lập ma trận nơi tạo lỗi: advice của business service/Audit, security handler, Gateway reactive handler; ghi lớp đã có và điểm chưa cùng contract. Không scaffold lại các file đã có.
2. Đối chiếu mã đang được caller sử dụng với catalog. Chỉ thêm/sửa code khi thật sự thiếu: tên ổn định, status đúng, đủ vi/en; mỗi status có một defaultForStatus, mã nghiệp vụ cùng status không tự nhận default.
3. Khi triển khai có thay catalog, dùng `node scripts/generate-errors.mjs` tại gốc repo để sinh lại; bàn giao cùng các output. Lệnh này là hướng dẫn cho người triển khai, chưa chạy khi biên soạn detail.
4. Sửa ApiError/ApiException/advice ở đúng nơi cần thiết; backend lấy message từ generated enum. Không sửa tay ErrorCode.java, error-codes.generated.ts hoặc errors.generated.json.
5. Đối chiếu entry point/access denied của servlet và Gateway; ControllerAdvice không thay thế security handler. Gateway không ghi lại body khi response đã committed, không nuốt lỗi rồi trả 200.
6. Đối chiếu PageResponse và các caller hiện có; giữ content DTO, index trang và tổng số phần tử. Chỉ sửa chênh lệch trong phạm vi contract được duyệt.
7. Đối chiếu resolver lỗi của cả Next.js và React; known code → locale tương ứng; unknown code → status mặc định → INTERNAL_ERROR. Đổi ngôn ngữ phải dịch lại lỗi, không hiển thị raw message do server trả.
8. Người phụ trách chạy kiểm tra được phép theo mục 7 và lưu bằng chứng; nếu đang sửa task detail thì không chạy generator, test, lint, typecheck hoặc build.

**Không làm:** dịch dữ liệu người dùng, viết lại UI của mọi màn, sửa generated thủ công, thêm network Error Service, thêm dependency chỉ để bọc 6 trường lỗi, đổi toàn bộ success response ngoài phạm vi.

## 7. Tiêu chí nghiệm thu để người phụ trách tự kiểm tra

Dữ liệu ví dụ là fixture. Không gửi request lỗi vào production; không đưa secret thật vào exception để kiểm tra redaction. Dùng chuỗi đánh dấu giả và xác nhận nó không xuất hiện trong response/evidence nhạy cảm.

| Mã | Chuẩn bị/thao tác | Kết quả mong đợi |
|---|---|---|
| AC-01 | Gây validation, unauthenticated, forbidden, not-found, conflict và unexpected trên môi trường kiểm tra | Mỗi response có đủ 6 trường đúng kiểu; status/code khớp bảng mục 3; không rơi về HTML hoặc 200 |
| AC-02 | Sau thay đổi catalog đã duyệt, sinh output và người phụ trách chạy `node scripts/generate-errors.mjs --check` | Không drift; 10 module Java và hai frontend có cùng danh mục/status; vi/en đầy đủ, generated không sửa tay |
| AC-03 | Exception giả chứa SQL/password marker; body JSON hỏng chứa giá trị nhạy cảm giả | Response chỉ có message catalog, không có raw exception, SQL, stack trace hoặc rejectedValue nhạy cảm |
| AC-04 | Token lỗi ở Gateway và khi gọi service trực tiếp | Đều trả 401/UNAUTHENTICATED theo contract, không chỉ advice của controller đúng |
| AC-05 | Lỗi nghiệp vụ dùng ApiException với code có sẵn | Giữ đúng code/status/message của domain, không bị đổi thành INTERNAL_ERROR hoặc lỗi generic không cần thiết |
| AC-06 | Cả hai frontend nhận code lạ/status 409/message nguy hiểm giả; tiếp theo code/status đều không biết | Lần đầu hiển thị RESOURCE_CONFLICT theo locale; lần sau INTERNAL_ERROR; không hiện raw message |
| AC-07 | Nhận known code rồi đổi vi/en | Giữ code/logic, thông báo đổi theo locale; không dùng bản dịch làm khóa nghiệp vụ |
| AC-08 | Trả page rỗng rồi page có DTO; kiểm tra default size/max và invalid input theo quyết định mục 5 | Content/tổng/trang đúng, không serialize entity; page rỗng không 404; invalid input đúng quy tắc đã ghi, chưa chốt thì chưa PASS phần này |
| AC-09 | Gateway gặp lỗi khi response đã committed; method không hỗ trợ gây 405 | Không ghi JSON lỗi lần hai vào response đã gửi; 405 không bị đổi thành 500 |

Chưa chạy các AC này. Kiểm tra generator/local không thay thế kết quả CI thật; không báo CI PASS khi chưa có evidence.
