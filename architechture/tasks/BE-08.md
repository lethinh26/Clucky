## 3. Phạm vi phải đối chiếu

| Bảng → entity có sẵn | Cột/ràng buộc cần chú ý |
|---|---|
| `reviews` → `Review` | customer_id/product_id/order_id là ID ngoài service; rating CHECK 1..5; comment/status/created_at; SQL hiện không có store_id |
| `review_replies` → `ReviewReply` | review_id là FK nội bộ; responder_id/responder_role/content/created_at; không nối User bên Identity |
| `daily_store_stats` → `DailyStoreStats` | UNIQUE(store_id,stat_date); stat_date là DATE; order_count INT; revenue/cod_amount/transfer_amount NUMERIC(12,0) |

Repository tương ứng nằm cùng service, kế thừa JpaRepository với ID Long. Ưu tiên method đã có; chỉ thêm query thực sự cần cho task nhận đầu ra, không dựng CRUD API để chứng minh repository hoạt động.

## 4. Thứ tự thực hiện và cách ánh xạ

1. Lập bảng đối chiếu ngay trong phần bàn giao: bảng/cột SQL → field Java → kiểu/nullability/constraint → khớp hoặc chênh lệch. Đọc V2 và entity trước, chưa sửa DB.
2. Làm reviews trước review_replies, rồi daily_store_stats với cùng một ngày cho hai quán. Đối chiếu rating boundary 1/5, tiền và DATE. Không tự thêm store_id vào review hay join Order để đáp ứng quyền quán; phần đó cần contract domain.
3. BIGINT/BIGSERIAL dùng Long; NUMERIC dùng BigDecimal đúng precision/scale; TIMESTAMPTZ dùng Instant như code hiện có; DATE dùng LocalDate, TIME dùng LocalTime. Cột nullable cần kiểu cho phép null. Không dùng float/double cho tiền.
4. So default SQL với giá trị khởi tạo Java: DB default không tự áp dụng khi ORM gửi null tường minh. Kiểm tra trường bắt buộc được gán từ đâu; không tùy tiện thêm callback hoặc đổi luật nghiệp vụ.
5. Chỉ sửa mapping bị lệch. Giữ FK trong schema đang sở hữu; ID thuộc service khác không thành JPA association/FK xuyên schema. HTTP trả DTO, không expose entity.
6. Nếu cần đổi bảng/index: ghi chênh lệch, lý do, ảnh hưởng dữ liệu cũ và migration mới để duyệt. Không sửa V1/V2 đã áp dụng, không dùng ddl-auto=update/create, không bật baseline tự động để bỏ qua DB có dữ liệu.
7. Khi người phụ trách tự kiểm tra, dùng database riêng và dữ liệu giả theo mục 7; ghi kết quả đọc/ghi, constraint và restart. Không xóa volume/DB thật để làm sạch lỗi.

**Không làm:** endpoint nghiệp vụ, seed tài khoản/credential thật, truy cập database service khác, mở rộng tích hợp ngoài phạm vi. Tiền/ID/thời điểm ở các ví dụ là fixture, không phải dữ liệu sản xuất.
