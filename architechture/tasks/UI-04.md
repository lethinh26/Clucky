## UI-04 — Thiết lập Eureka Server và cấu hình client để Gateway, các service đăng ký và tìm đúng địa chỉ kết nối

**Phụ trách:** Nguyễn Duy Quang Nhật · **Sprint:** 1 · **Ước lượng:** 2 SP
**Phụ thuộc:** —

### 1. User Story

- **Là người phát triển**, tôi muốn thiết lập Eureka Server và cấu hình client để Gateway, các service đăng ký và tìm đúng địa chỉ kết nối.

### 2. Công việc

- Rà application/service IDs với config-repo/Gateway. Viết bảng appName → registry ID → route consumer → advertised address cho local/container, không chỉ liệt kê tên trong dashboard.
- Nối Discovery nhận Config Server theo UI-03, giữ name/import bootstrap local và chuyển runtime settings phù hợp. Config Server phải khởi động độc lập trước registry, tránh registry cần chính nó để tải config.
- Giữ server register/fetch semantics phù hợp standalone, không thêm HA peers. Chốt hostname/interface/port theo môi trường, tách server self URL với URL clients dùng.
- Rà client bootstrap/defaultZone và instance metadata. Không chép Eureka config đầy đủ vào mọi local application.yml khi shared Config Server đã quản lý; README mẫu phải ghi rõ có hiệu lực hay chỉ hướng dẫn.
- Chốt lease/self-preservation/readiness behavior và tín hiệu stale instance; không tắt self-preservation chỉ để ca test xóa instance nhanh. Multi-instance cùng app phải có identity không va chạm nếu môi trường thực cần.
- Phối hợp UI-05 kiểm Gateway resolve lb:// qua registry và error khi không có instance; không coi HTTP200 dashboard chứng minh routing hoạt động hoặc triển khai lại route/auth tại đây.
- Bàn giao runbook startup infra→Config→Eureka→business→Gateway, restart/unregister/timeout expectations và cách lấy evidence không secret. Owner chạy khi được yêu cầu, lượt viết detail không bật service/Docker.

### 3. Contract và đầu ra

| Môi trường / phần | Quy tắc |
| --- | --- |
| Local | EUREKA_URL dùng localhost:8761/eureka/ từ process host; port/name rõ, không nhầm dashboard URL với service-url |
| Container | Dùng địa chỉ network service discovery-server:8761/eureka/ từ client container; localhost bên trong container không phải registry khác |
| Service ID | spring.application.name khớp route lb:// và cấu hình service; kiểm behavior casing thực, không đổi tên tùy ý |
| Instance address | Host/IP/port được quảng bá phải reachable từ consumer/Gateway trong môi trường đó; UP không tự chứng minh reachability |
| Heartbeat/lease | Dùng policy được chốt; eviction timer10s không đồng nghĩa instance chết bị xóa sau10s, self-preservation có ảnh hưởng |
| Security | Registry/Actuator chỉ phạm vi hạ tầng được phép, không chứa token/password trong metadata hoặc expose qua frontend |

### 4. Tiêu chí hoàn thành

- Khởi động theo runbook, Discovery nhận config rồi client đăng ký: Đúng app/instance/port, không duplicate config hoặc vòng phụ thuộc Config↔Eureka
- Client host và container dùng EUREKA_URL riêng: Đều tới đúng registry; advertised address reachable từ consumer tương ứng, không localhost sai chỗ
- Gateway resolve lb://service có instance: Tới đúng instance; chỉ khi owner chạy mới có evidence routing, dashboard không thay được
- Restart/graceful stop/crash client: Heartbeat/stale/eviction theo lease/self-preservation policy, không đánh fail vì chưa xóa ngay10s
- Hai instance cùng app nếu được cấu hình hỗ trợ: Không overwrite identity; registry/client phân biệt đúng port/address
- Registry outage hoặc appName/URL sai: Signal/error rõ và recovery theo policy, không gọi trực tiếp backend từ frontend để bypass
- Rà metadata/dashboard/Actuator: Không secret/PII không cần, endpoint giới hạn hạ tầng; snapshot DONE không tự xác nhận runtime mới
- Bàn giao contract, mã lỗi và kết quả tự kiểm thử kèm commit, môi trường, bằng chứng; ghi rõ lỗi hoặc phần còn bị chặn.

### 5. Điểm cần chốt

- Runtime config Discovery chuyển qua Config Server thế nào: Nguyễn Duy Quang Nhật cùng UI-03; chặn đáp ứng architecture, depends_on không đủ
- Địa chỉ quảng bá/instance ID trong local/container và multi-instance: Owner service/UI-06; chặn reachability/collision
- Lease/self-preservation/health versus readiness, expected outage: Owner hạ tầng/UI-05; không hứa eviction tức thì
- Registry/Actuator exposure và metadata được phép: Owner hạ tầng/security; không đưa credential vào registry
