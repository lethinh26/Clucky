## 1. Làm xong task này thì dùng được gì?

Eureka registry độc lập cho business services/Gateway đăng ký và tìm instance theo application name, không hardcode địa chỉ business service ở frontend. Owner biết local/container dùng URL nào, instance quảng bá địa chỉ nào và cách kiểm tra heartbeat/restart.

Không triển khai Gateway business route/auth, HA registry cluster hoặc load-balance database. Snapshot DONE được giữ; registry dashboard có instance chưa chứng minh API nghiệp vụ đúng hoặc Gateway đã resolve được địa chỉ đó.

## 2. Bắt đầu từ đâu? Có gap Config Server

Theo architecture/AGENTS, runtime config qua Config Server, local bootstrap-only. Cần hoàn thiện Discovery theo yêu cầu này thay vì coi có depends_on Config Server là đã đáp ứng; không tự chấp nhận ngoại lệ chưa được duyệt.

## 3. Contract registry/client

| Môi trường / phần | Quy tắc |
|---|---|
| Local | EUREKA_URL dùng localhost:8761/eureka/ từ process host; port/name rõ, không nhầm dashboard URL với service-url |
| Container | Dùng địa chỉ network service discovery-server:8761/eureka/ từ client container; localhost bên trong container không phải registry khác |
| Service ID | spring.application.name khớp route lb:// và cấu hình service; kiểm behavior casing thực, không đổi tên tùy ý |
| Instance address | Host/IP/port được quảng bá phải reachable từ consumer/Gateway trong môi trường đó; UP không tự chứng minh reachability |
| Heartbeat/lease | Dùng policy được chốt; eviction timer10s không đồng nghĩa instance chết bị xóa sau10s, self-preservation có ảnh hưởng |
| Security | Registry/Actuator chỉ phạm vi hạ tầng được phép, không chứa token/password trong metadata hoặc expose qua frontend |

Registry không thay phân quyền backend và không lưu session/business data. Service không đăng ký được phải có signal rõ, không để frontend bỏ Gateway rồi gọi URL nội bộ như workaround.

## 4. Thứ tự hoàn thiện

1. Rà application/service IDs với config-repo/Gateway. Viết bảng appName → registry ID → route consumer → advertised address cho local/container, không chỉ liệt kê tên trong dashboard.
2. Nối Discovery nhận Config Server theo UI-03, giữ name/import bootstrap local và chuyển runtime settings phù hợp. Config Server phải khởi động độc lập trước registry, tránh registry cần chính nó để tải config.
3. Giữ server register/fetch semantics phù hợp standalone, không thêm HA peers. Chốt hostname/interface/port theo môi trường, tách server self URL với URL clients dùng.
4. Rà client bootstrap/defaultZone và instance metadata. Không chép Eureka config đầy đủ vào mọi local application.yml khi shared Config Server đã quản lý; README mẫu phải ghi rõ có hiệu lực hay chỉ hướng dẫn.
5. Chốt lease/self-preservation/readiness behavior và tín hiệu stale instance; không tắt self-preservation chỉ để ca test xóa instance nhanh. Multi-instance cùng app phải có identity không va chạm nếu môi trường thực cần.
6. Phối hợp UI-05 kiểm Gateway resolve lb:// qua registry và error khi không có instance; không coi HTTP200 dashboard chứng minh routing hoạt động hoặc triển khai lại route/auth tại đây.
7. Bàn giao runbook startup infra→Config→Eureka→business→Gateway, restart/unregister/timeout expectations và cách lấy evidence không secret. Owner chạy khi được yêu cầu, lượt viết detail không bật service/Docker.
