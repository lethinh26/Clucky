## 1. Làm xong task này thì dùng được gì?

BE-33 dùng một bộ rule phí ship nhất quán cho base fee/per-km/free threshold/store override và PICKUP. Order preview/checkout nhận cùng cách tính khi input/config giống nhau; có bảng ca biên với expected amount để người làm không phải tự đoán.

Task này hoàn thiện rule dùng bên trong BE-33, không tạo API tính phí thứ hai hoặc một bộ công thức riêng ở frontend. Không Maps/GPS, gán shipper hay đổi UI INT-65; MVP dùng khu vực/khoảng cách cấu hình sẵn theo SRS.

## 3. Bảng rule phải bàn giao

| Thành phần | Quy tắc bắt buộc / quyết định cần cụ thể hóa |
|---|---|
| PICKUP | Không tính giao tận nơi; tránh gọi lookup distance không cần thiết |
| DELIVERY | Chọn config đúng store/global theo policy, rồi tính với amount/distance từ nguồn được phép |
| Base/per-km | Dùng BigDecimal; công thức tuyến tính, phần km làm tròn và thứ tự rounding phải được duyệt, không suy từ tên cột |
| Free threshold | Chốt amount trước/sau voucher/điểm/phí, biên bằng ngưỡng và ý nghĩa null/0 |
| Store override | Chốt override cả row hay từng trường và precedence; không lấy config của quán khác hoặc first row tùy ý |
| Config/distance thiếu, âm hoặc nhiều config xung đột | Lỗi rõ; không mặc định fee=0 để checkout tiếp |
| Config thay đổi | Phí đơn đã tạo là snapshot, không tự tính lại shipment lịch sử bằng config mới |

Đầu vào/đầu ra dùng contract calculate-fee BE-33. Có thể bàn giao breakdown/config áp dụng nếu owner chốt field; không hứa DTO đang có sẵn. Số tiền checkout cần Order tính từ dữ liệu thật, không tin subtotal giả của frontend để vượt free threshold.

## 4. Thứ tự triển khai cụ thể

1. Cùng BE-33/Order chốt request delivery type/store/amount/distance-khu vực, đơn vị và nguồn dữ liệu. Viết bảng precedence/rounding/threshold trước khi chọn expected amount.
2. Chọn config một cách xác định: store override hoặc global theo policy; phát hiện thiếu/trùng. Nếu cần constraint unique cho store và global null, thêm migration mới phù hợp semantics DB, không giả unique(storeId) tự chặn nhiều null.
3. Viết một luồng tính phí dùng trong calculate-fee BE-33: validate boundary, chọn config, xét PICKUP/free threshold theo thứ tự duyệt, tính tiền và làm tròn. Không dùng float/double cho tiền, không cộng phí nhiều lần giữa Shipping và Order.
4. Giữ nguồn distance/config an toàn: map khu vực được cấu hình theo docs nếu đó là phương án được duyệt; không thêm Maps API hoặc gọi mạng để đo vị trí. Input không xác minh được phải báo lỗi, không âm thầm dùng 0 km.
5. Chốt numeric bounds theo schema/DTO, kết quả không âm hoặc overflow; admin sửa config có validation. Null freeFromAmount không được vô tình ép thành 0 rồi miễn phí mọi đơn.
6. Bàn giao bảng ví dụ/ca biên và rule version cho BE-24/25/33. Preview không bảo đảm phí giữ nguyên nếu dữ liệu/config đổi; checkout revalidate và snapshot đúng contract, không ghi lại phí đơn cũ.

## 7. Tiêu chí nghiệm thu với bảng tính mẫu

Chưa chạy kiểm chứng. **Fixture có điều kiện:** chỉ nếu policy duyệt công thức base + distance × perKm, miễn phí khi amount >= threshold và override cả row. Global base=10.000, perKm=5.000, threshold=200.000; quán A override base=15.000, perKm=4.000, cùng threshold; distance=2 km. Nếu policy khác, sửa expected tương ứng trước nghiệm thu.

| AC | Input / thao tác | Kết quả theo fixture có điều kiện |
|---|---|---|
| AC-01 | DELIVERY quán dùng global, amount=100.000, distance=2 | Fee=20.000, không cộng lại base hoặc shipping ở Order lần hai |
| AC-02 | Quán A cùng input | Fee=23.000 từ override; quán khác không bị áp config A |
| AC-03 | Global amount=199.999 / 200.000 / 200.001 | Fee=20.000 / 0 / 0 theo giả định inclusive đã duyệt |
| AC-04 | PICKUP với cùng order amount | Fee=0 theo SRS, không bắt buộc có distance giao hàng |
| AC-05 | DELIVERY thiếu distance/config, distance âm, config trùng hoặc tiền vượt precision | Lỗi đúng policy, không âm thầm trả 0 hoặc chọn row bất kỳ |
| AC-06 | Distance lẻ 1,25 km, null/0 threshold và discount làm amount qua biên | Expected từ bảng rounding/amount đã chốt; không dùng ví dụ nguyên km để bỏ qua ca này |
| AC-07 | Client giả amount cao hơn để đạt free threshold; config đổi sau preview | Checkout dùng nguồn Order tin cậy và contract revalidate, không tin preview cũ/client amount |
| AC-08 | Thay config rồi đọc đơn/shipment đã tạo | Phí snapshot cũ giữ nguyên, calculation mới theo config mới; không viết lại lịch sử |
