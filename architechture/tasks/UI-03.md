## 1. Làm xong task này thì dùng được gì?

Config Server cung cấp shared/service/profile configuration đúng application name, để service chỉ giữ bootstrap local và lấy runtime settings từ nguồn cấu hình tập trung/env. Người triển khai biết local/container tìm config-repo ở đâu, cách override và lỗi thiếu config/secret được xử lý thế nào.

Dù ID UI, đây là task hạ tầng Config Server, không trang giao diện. Không triển khai business API/tạo DB từng service hoặc đổi native sang Git ngoài yêu cầu. Snapshot DONE giữ nguyên, chưa xác nhận lại runtime.

## 2. Bắt đầu từ đâu?

Đối chiếu source ngày 05/11, chưa boot/build/Docker.

| Vị trí từ gốc repo | Hiện trạng / gap |
|---|---|
| `backend/config-server/src/main/java/com/clucky/configserver/ConfigServerApplication.java` | Có @EnableConfigServer; không scaffold lại |
| `backend/config-server/src/main/resources/application.yml` | Native profile, port8888, search locations từ CONFIG_SERVER_NATIVE_SEARCH_LOCATIONS với fallback relative paths |
| `config-repo/application.yml`, `application-dev.yml`, `application-prod.yml` | Shared DB/Redis/Kafka/Eureka/security và profile overrides; prod yêu cầu env, không phải giá trị secret đã cấp |
| `config-repo/*-service.yml`, `api-gateway*.yml` | Runtime từng service, namespace schema/port/route/media/mail theo domain |
| `backend/catalog-store-service/src/main/resources/application.yml` và bootstrap các business service | name + configserver import; cần rà tên/profile khớp file, không chép cả runtime config vào local |
| `docker-compose.yml`, `backend/config-server/Dockerfile` | Compose build context hiện ./backend/config-server nhưng Dockerfile gọi Gradle :config-server từ workspace; cần đối chiếu context chứa root settings/build trước kết luận đóng gói được |

Profile hiện có `mail.sender.*` trong shared dev/prod nhưng Notification binding dùng `mail-sender.*`. Không tự coi hai namespace tương đương; chốt sửa mapping cùng BE-57, không báo override mail đã hiệu lực chỉ vì env xuất hiện trong file. `config-repo/README.md` đang bị xóa ở working tree, không tự phục hồi thay đổi của người dùng.

## 3. Contract cấu hình/bàn giao

| Thành phần | Quy tắc |
|---|---|
| Application/profile | spring.application.name và active profiles khớp file; response property sources cần thể hiện đúng nguồn/precedence |
| Native local | Relative search path phụ thuộc working directory; runbook ghi lệnh/cwd hoặc absolute env path rõ |
| Native container | Mount config-repo read-only tại đường CONFIG_SERVER_NATIVE_SEARCH_LOCATIONS trỏ tới, không dùng localhost host path trong container |
| Secret | Placeholder/env/runtime secret store, không commit password/token/service-account; config endpoints không được public cho frontend |
| Client bootstrap | CONFIG_SERVER_URL và application name/profile; config import fail-fast/fallback theo policy, không âm thầm khởi động bằng config sai |
| Update config | Reload/restart theo cơ chế thực có; không hứa hot refresh nếu chưa implement |

Thứ tự yêu cầu: infrastructure → Config Server → Eureka → business → Gateway → frontends. Config Server không được chờ discovery client để tải chính cấu hình cần khởi động, gây vòng phụ thuộc.

## 4. Thứ tự hoàn thiện

1. Lập inventory application name/profile/file/owner và phân biệt bootstrap/runtime. Ghi gap Discovery config local ở UI-04, không tự viết lại tất cả service trong task này.
2. Rà native locations từ cwd local và volume container; bảo đảm source thực được mount, không fallback vào thư mục cũ khác rồi trả config không mong muốn.
3. Đối chiếu property sources/precedence của shared/service/profile bằng giá trị giả không nhạy cảm, đặc biệt namespace mail-sender và schema theo service. Không dùng HTTP200 config endpoint làm bằng chứng client bind đúng.
4. Rà Docker build context/Dockerfile/root Gradle layout, healthcheck command có trong runtime image và readiness; owner sửa tối thiểu khi triển khai, không tự chạy Docker ở lượt viết này.
5. Chốt required env prod, lỗi thiếu config/secret và quyền mạng/auth Config Server/Actuator. Không trả config chứa secret qua Gateway public hoặc dump property sources vào báo cáo.
6. Viết runbook local/container/cwd/profile/env cấp ở đâu, cách cập nhật/restart và xác minh bằng thông tin an toàn. Giữ cấu hình native hiện có; không thêm config UI, Git server hoặc hot-reload framework khi chưa cần.
7. Bàn giao UI-04/business owners bootstrap contract và known gaps. Evidence runtime do người phụ trách chạy khi được yêu cầu; không coi compile/config file tồn tại là service đã nhận config.
