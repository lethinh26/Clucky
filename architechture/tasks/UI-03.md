## UI-03 — Thiết lập Config Server và config-repo để các service tải cấu hình chung, riêng và theo môi trường từ một nguồn

**Phụ trách:** Trần Nguyễn Hữu Khánh · **Sprint:** 1 · **Ước lượng:** 3 SP
**Phụ thuộc:** —

### 1. User Story

- **Là người phát triển**, tôi muốn thiết lập Config Server và config-repo để các service tải cấu hình chung, riêng và theo môi trường từ một nguồn.

### 2. Công việc

- Lập inventory application name/profile/file/owner và phân biệt bootstrap/runtime. Ghi gap Discovery config local ở UI-04, không tự viết lại tất cả service trong task này.
- Rà native locations từ cwd local và volume container; bảo đảm source thực được mount, không fallback vào thư mục cũ khác rồi trả config không mong muốn.
- Đối chiếu property sources/precedence của shared/service/profile bằng giá trị giả không nhạy cảm, đặc biệt namespace mail-sender và schema theo service. Không dùng HTTP200 config endpoint làm bằng chứng client bind đúng.
- Rà Docker build context/Dockerfile/root Gradle layout, healthcheck command có trong runtime image và readiness; owner sửa tối thiểu khi triển khai, không tự chạy Docker ở lượt viết này.
- Chốt required env prod, lỗi thiếu config/secret và quyền mạng/auth Config Server/Actuator. Không trả config chứa secret qua Gateway public hoặc dump property sources vào báo cáo.
- Viết runbook local/container/cwd/profile/env cấp ở đâu, cách cập nhật/restart và xác minh bằng thông tin an toàn. Giữ cấu hình native hiện có; không thêm config UI, Git server hoặc hot-reload framework khi chưa cần.
- Bàn giao UI-04/business owners bootstrap contract và known gaps. Evidence runtime do người phụ trách chạy khi được yêu cầu; không coi compile/config file tồn tại là service đã nhận config.

### 3. Contract và đầu ra

| Thành phần | Quy tắc |
| --- | --- |
| Application/profile | spring.application.name và active profiles khớp file; response property sources cần thể hiện đúng nguồn/precedence |
| Native local | Relative search path phụ thuộc working directory; runbook ghi lệnh/cwd hoặc absolute env path rõ |
| Native container | Mount config-repo read-only tại đường CONFIG_SERVER_NATIVE_SEARCH_LOCATIONS trỏ tới, không dùng localhost host path trong container |
| Secret | Placeholder/env/runtime secret store, không commit password/token/service-account; config endpoints không được public cho frontend |
| Client bootstrap | CONFIG_SERVER_URL và application name/profile; config import fail-fast/fallback theo policy, không âm thầm khởi động bằng config sai |
| Update config | Reload/restart theo cơ chế thực có; không hứa hot refresh nếu chưa implement |

### 4. Tiêu chí hoàn thành

- Owner chạy Config Server local từ cwd đã ghi, client request đúng app/profile: Nguồn/config đúng, không đọc nhầm fallback path; client bind đúng trường thử
- Shared/service/profile có giá trị khác nhau ở fixture: Precedence đúng contract, không namespace mail.sender bị tưởng là mail-sender
- Container với mounted repo/read-only path và build context chuẩn: Đóng gói/healthcheck/import đúng khi được chạy; không thiếu root Gradle hoặc mount sai
- Sai app/profile/path hoặc thiếu env bắt buộc: Lỗi/fallback theo policy rõ, không âm thầm chạy schema/host sai
- Rà endpoints/logs/Actuator và response evidence: Không secret trong frontend/public/log, evidence chỉ metadata an toàn
- Đổi config rồi reload/restart theo runbook: Client nhận thay đổi đúng cơ chế thực có, không tuyên bố tự refresh nếu chưa hỗ trợ
- Bàn giao contract, mã lỗi và kết quả tự kiểm thử kèm commit, môi trường, bằng chứng; ghi rõ lỗi hoặc phần còn bị chặn.

### 5. Điểm cần chốt

- Canonical native path/cwd/build context và readiness: Trần Nguyễn Hữu Khánh cùng UI-06/owner deploy; chặn local/container runbook
- Profile precedence/namespace mail-sender/required env: Config cùng BE-57/domain owners; chặn binding đúng
- Endpoint exposure, secret injection, refresh/restart policy: Owner hạ tầng; không tự mở config cho frontend hoặc hứa refresh chưa có
