## UI-28 — Quản lý voucher thường; giữ phần đề xuất chi nhánh và banner ở trạng thái backlog, chưa triển khai nghiệp vụ

**Phụ trách:** Cao Tất Thành · **Sprint:** 1 · **Ước lượng:** 3 SP
**Phụ thuộc:** —

### 1. User Story

- **Là Admin**, tôi muốn quản lý voucher thường; giữ phần đề xuất chi nhánh và banner ở trạng thái backlog, chưa triển khai nghiệp vụ để quản lý dữ liệu và thao tác nghiệp vụ đúng quyền.

### 2. Công việc

- Dựng voucher form/scope selector
- Validate điều kiện/thời gian
- Trình bày trạng thái proposal/banner mà không giả integration

**Không bao gồm:** kéo BE-35, BE-36 vào Sprint 2 hoặc thay eligibility bằng logic UI.

### 3. Contract và đầu ra

| Thành phần | Chi tiết cần bàn giao |
| --- | --- |
| Đầu vào / nguồn tin cậy | Voucher/form fixtures, role/store/scope và trạng thái proposal/banner nếu minh họa. |
| Đầu ra / contract | Promotions UI với voucher CRUD, khung proposal/banner có trạng thái phạm vi rõ. |
| Điểm giao tiếp / deliverable đã cam kết | react/pages/Promotions |

### 4. Tiêu chí hoàn thành

- Promotions UI với voucher CRUD, khung proposal/banner có trạng thái phạm vi rõ.
- STORE voucher: Yêu cầu store theo contract
- Date/limit sai: Validation rõ
- Chức năng backlog: Không báo đã hoạt động thật
- Admin tạo voucher STORE A, reload và Customer A validate/preview: Field persisted đúng, discount theo server và chỉ trong điều kiện được duyệt
- Form sai: Hiển thị field/code lỗi, không đóng mất input
- Voucher STORE dùng ngoài quán: Bị từ chối
- Save success rồi reload: Rule đã lưu đúng
- Customer dùng voucher A ở B hoặc qua hạn/quota: Bị từ chối, không giữ discount mock hoặc total stale
- Save lỗi/duplicate code hoặc Manager gọi Admin CRUD: Không success giả/trái quyền, form có hướng sửa
- Admin tạo store/product và voucher thường rồi Customer browse/preview: Record persisted đúng, menu phản ánh và discount theo backend
- Admin save thành công: Public/readback đúng record
- Voucher STORE ở quán khác: Không giảm tiền
- Invalid product/voucher: Không tạo record nửa vời
- Voucher STORE A dùng tại B hoặc đã hết điều kiện: Không giảm giá sai và không dùng fallback mock
- Form invalid hoặc request save thất bại: Không có dữ liệu nửa vời, giữ form/lỗi đúng; không báo thành công từ local row
- Bàn giao contract, mã lỗi và kết quả tự kiểm thử kèm commit, môi trường, bằng chứng; ghi rõ lỗi hoặc phần còn bị chặn.

### 5. Điểm cần chốt

- MVP tích hợp ở INT-62 chỉ voucher thường; không coi task UI bao gồm backend approve/banner.
