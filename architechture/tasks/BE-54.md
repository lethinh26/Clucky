## BE-54 — Kết nối menu qua Gateway và triển khai cache theo quán, làm mới dữ liệu khi giá hoặc trạng thái bán thay đổi

**Phụ trách:** Nguyễn Duy Quang Nhật · **Sprint:** 2 · **Ước lượng:** 5 SP
**Phụ thuộc:** BE-20, BE-22, BE-12

### 1. User Story

- **Là người phát triển**, tôi muốn kết nối menu qua Gateway và triển khai cache theo quán, làm mới dữ liệu khi giá hoặc trạng thái bán thay đổi để triển khai và tích hợp đúng dữ liệu, quyền và contract của hệ thống.

### 2. Công việc

- Cache key/value/TTL/freshness, invalidation store/global, Redis failure và route discovery
- Browse/search/detail theo contract thật, không fallback mock
- Đo performance <500ms từng nằm TEST-13 vẫn HOÃN, không đưa vào DoD sprint
- Lập key matrix và nguồn mutation làm thay đổi giá/availability
- Chốt stale-fill/invalidation/fallback với BE-12 và Order
- Triển khai cache read và invalidate sau commit
- Kiểm cold/warm, query khác, update concurrent và Redis lỗi

### 3. Contract và đầu ra

- Public catalog routes qua Gateway/Eureka; key gồm phạm vi query/locale nếu ảnh hưởng response theo policy
- TTL theo Config Server/BE-12; 10 phút cấu hình hiện có không tự là freshness SLA
- Cache chỉ snapshot đọc; quyền/admin responses không được đưa vào public key

### 4. Tiêu chí hoàn thành

- Cold rồi warm cùng store/query: Cùng dữ liệu hợp lệ, warm không đổi semantics
- Đổi store/category/keyword/page: Không trộn giá hoặc tập món
- Update giá/availability thành công: Menu đổi theo freshness policy, checkout dùng giá thật
- Mutation rollback: Cache không lộ dữ liệu chưa commit
- Read cũ đang fill khi mutation commit: Không ghi đè version mới bằng stale snapshot ngoài policy
- Redis unavailable/timeout: Fallback/error đã chốt, không trả menu mẫu hoặc empty giả thành công
- Global catalog mutation: Invalidate mọi phạm vi bị ảnh hưởng, không vô cớ xóa key service khác
- Store đóng, món inactive/soldOut/combo thiếu thành phần: Response/availability theo rule, không stale chéo quán
- Gateway không tìm thấy upstream hoặc route sai: Lỗi route/upstream rõ, FE không gọi thẳng service để né
- Cache cũ khác schema/version sau deploy: Bỏ/đọc an toàn theo version policy, không deserialize lỗi lộ stack
- Search không có dữ liệu, API lỗi và đổi vi/en: Empty/error/loading rõ; không mất context URL hoặc chọn quán
- Bàn giao contract, mã lỗi và kết quả tự kiểm thử kèm commit, môi trường, bằng chứng; ghi rõ lỗi hoặc phần còn bị chặn.

### 5. Điểm cần chốt

- Owner Catalog chốt canonical cache hay response cache, TTL/freshness và fallback Redis
- Chốt phạm vi invalidate khi global product thay đổi và version schema khi deploy; không thêm framework phân tán nếu không cần
