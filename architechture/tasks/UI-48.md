## UI-48 — Sửa responsive và thao tác bàn phím trên voucher, điểm thành viên và thông báo

**Phụ trách:** Cao Tất Thành · **Sprint:** 1 · **Ước lượng:** 2 SP
**Phụ thuộc:** —

### 1. User Story

- **Là người phát triển**, tôi muốn sửa responsive và thao tác bàn phím trên voucher, điểm thành viên và thông báo để triển khai và tích hợp đúng dữ liệu, quyền và contract của hệ thống.

### 2. Công việc

- Kiểm tra badge/list/form ở viewport hẹp
- Kiểm tra focus/aria/selected state
- Đối chiếu label và feedback vi/en

**Không bao gồm:** triển khai backend promotion/notification.

### 3. Contract và đầu ra

| Thành phần | Chi tiết cần bàn giao |
| --- | --- |
| Đầu vào / nguồn tin cậy | UI-22, UI-28, UI-32, UI-45 fixtures, long text, empty/error/read states. |
| Đầu ra / contract | Responsive/a11y fixes của Promotion/Notification. |
| Điểm giao tiếp / deliverable đã cam kết | Domain UI checklist |

### 4. Tiêu chí hoàn thành

- Responsive/a11y fixes của Promotion/Notification.
- List nhiều thông báo: Scroll/paging không mất action
- Voucher code dài: Không che điều kiện/nút
- Mark-read keyboard: Có focus và feedback rõ
- Flow backend thật trên các viewport/browser đã chốt, cả hai app: Không mất nội dung/action, UI state và quyền đúng, evidence ghi viewport
- Long product/address: Không che action hoặc tràn ngang
- API error trên mobile: Vẫn có retry/validation đọc được
- Modal/drawer: Action/close keyboard truy cập được
- Tên/địa chỉ dài, vi/en và API error trên màn nhỏ: Không tràn che CTA, validation/retry đọc và dùng được
- Mở form modal/drawer bằng keyboard rồi đóng: Focus/control truy cập được, không kẹt nền hoặc mất nút save/close
- Bàn giao contract, mã lỗi và kết quả tự kiểm thử kèm commit, môi trường, bằng chứng; ghi rõ lỗi hoặc phần còn bị chặn.

### 5. Điểm cần chốt

- Phân biệt phần voucher thường đang tích hợp với proposal/banner backlog khi nghiệm thu.
