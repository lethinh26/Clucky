## 1. Làm xong task này thì dùng được gì?

Hai frontend dùng một Gateway URL; request đi đúng service qua Eureka thay vì hard-code cổng từng backend. Người nhận task phải bàn giao bảng route và cách phân biệt lỗi auth, không có route, không có upstream; không chỉ tạo app Spring chạy được.

Phạm vi là Gateway app và route `lb://`. Không expose tất cả endpoint nội bộ, không thay backend kiểm tra ownership/storeId, không gộp triển khai auth của INT-53 hoặc nghiệp vụ audit của BE-43 vào task này.

## 2. Bắt đầu từ đâu? Source đã có gì?

Đối chiếu source ngày **05/11/2026**, chưa chạy Gateway:

- `backend/api-gateway` đã có WebFlux Gateway, LoadBalancer, Eureka/Config client, resource server và Redis. Không tạo project mới hoặc chuyển sang MVC.
- `src/main/resources/application.yml` chỉ khai báo tên app và import Config Server; runtime routes/CORS nằm ở `config-repo/api-gateway.yml`.
- Config đã có routes identity, catalog, order, payment, promotion, shipping, notification, review/report và audit; dùng `lb://...`, không phải route rỗng cần dựng lại.
- `SecurityConfig` đã phân biệt public/authenticated/internal và kiểm tra JWT/session; `CorrelationIdFilter` đã tồn tại. Route đúng không đồng nghĩa request được phép truy cập.
- Next `lib/api.ts` chọn Gateway qua `API_URL`/`INTERNAL_API_URL` phía server hoặc `NEXT_PUBLIC_API_URL` phía browser. React có adapter riêng tại `src/lib/api.ts`; rà soát cả hai, không chỉ sửa một `.env`.

**Việc đầu tiên:** lập bảng đối chiếu predicate hiện tại với API docs và controller của service đích. Chỉ sửa sai khác có chứng cứ; đừng chép routes xuống local `application.yml`.

## 3. Contract route phải bàn giao

| Nhóm | Route đang có / yêu cầu khi hoàn thiện |
|---|---|
| Identity | `/api/auth/**`, `/api/users/**`, `/api/schedules/**` → `lb://IDENTITY-SERVICE`; giữ method/query/body và cookie theo auth contract |
| Catalog | `/api/stores/**`, `/api/catalog/**`, `/api/media/**` → `lb://CATALOG-STORE-SERVICE`; kiểm tra riêng media delete nội bộ, không suy ra mọi method đều public |
| Order | `/api/cart/**`, `/api/orders/**`, `/api/party-orders/**`, `/api/refund-requests/**` → `lb://CART-ORDER-SERVICE` |
| Nhóm còn lại | Ghi đầy đủ predicate, service ID, route ID và owner từ config đang có; đối chiếu audit `/api/audit-logs` với BE-43 |
| Prefix | Config hiện chưa khai báo rewrite ở các route trên; giữ nguyên `/api/...` nếu controller dùng cùng prefix. Chỉ thêm StripPrefix/RewritePath khi hai owner xác nhận |
| CORS | Origin FE được cho phép rõ ràng; preflight hợp lệ, credentials/cookie theo contract; không dùng origin wildcard để vượt lỗi |
| Lỗi | Giữ error shape đã công bố; phân biệt 401/403 với lỗi route/upstream; có correlation ID để truy vết, không trả stack trace/secret |

## 4. Thứ tự hoàn thiện

1. Đọc API spec, config và security matcher; tạo checklist từng method/path → route → service. Đánh dấu internal endpoint phải bị chặn ở cửa công khai, đặc biệt media delete.
2. Đối chiếu service ID với tên đăng ký Eureka; sửa config trung tâm nếu lệch. Không đổi sang URL host cố định để che lỗi discovery.
3. Kiểm tra thiết kế đường đi cho Catalog GET và Orders request có auth: path/query/header cần chuyển tiếp, response/error cần giữ. Không mở public Orders để thử route.
4. Chốt origin dev/prod với owner frontend; kiểm tra cấu hình preflight, credentials và response header chống lặp. Không tự mở thêm domain.
5. Rà soát frontend adapter/env example để mọi browser/server call tới Gateway phù hợp môi trường. Giữ secret/JWT key ngoài repository.
6. Soạn hướng dẫn người dùng kiểm chứng sau khi infra → Config → Eureka → service → Gateway sẵn sàng, gồm upstream bị dừng và request internal. Không tự chạy chuỗi này trong lần viết detail.
7. Bàn giao config diff, bảng route và lỗi còn mở cho INT-53/INT-54; nếu auth chưa chạy, ghi blocked ở AC tương ứng thay vì kết luận route hỏng.

## 5. Điểm cần chốt trước khi nghiệm thu

- **PIC Gateway + owner service:** prefix và method thật, các đường dẫn nội bộ không được publish. Quyền “authenticated” chưa đủ chứng minh endpoint chỉ dành cho service an toàn.
- **PIC Gateway + FE:** origin của từng môi trường, URL server-side/container, cookie/CORS. Chưa có domain production thì chỉ bàn giao mẫu cấu hình, không tự suy đoán.
- **INT-53:** phân công xử lý token/session/401/403; giữ middleware hiện có, không vô hiệu hóa auth để làm AC route pass.
- **BE-43:** audit route đã xuất hiện trong config nhưng phải đối chiếu contract/read permission; việc xuất hiện không chứng minh audit tích hợp xong.
