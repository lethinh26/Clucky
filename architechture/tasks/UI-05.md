## UI-05 — Thiết lập API Gateway, ánh xạ route qua Eureka và tích hợp xác thực để hai frontend gọi backend qua một đầu vào

**Phụ trách:** Trần Đức Anh · **Sprint:** 1 · **Ước lượng:** 3 SP
**Phụ thuộc:** —

### 1. User Story

- **Là người phát triển**, tôi muốn thiết lập API Gateway, ánh xạ route qua Eureka và tích hợp xác thực để hai frontend gọi backend qua một đầu vào.

### 2. Công việc

- Đọc API spec, config và security matcher; tạo checklist từng method/path → route → service. Đánh dấu internal endpoint phải bị chặn ở cửa công khai, đặc biệt media delete.
- Đối chiếu service ID với tên đăng ký Eureka; sửa config trung tâm nếu lệch. Không đổi sang URL host cố định để che lỗi discovery.
- Kiểm tra thiết kế đường đi cho Catalog GET và Orders request có auth: path/query/header cần chuyển tiếp, response/error cần giữ. Không mở public Orders để thử route.
- Chốt origin dev/prod với owner frontend; kiểm tra cấu hình preflight, credentials và response header chống lặp. Không tự mở thêm domain.
- Rà soát frontend adapter/env example để mọi browser/server call tới Gateway phù hợp môi trường. Giữ secret/JWT key ngoài repository.
- Soạn hướng dẫn người dùng kiểm chứng sau khi infra → Config → Eureka → service → Gateway sẵn sàng, gồm upstream bị dừng và request internal. Không tự chạy chuỗi này trong lần viết detail.
- Bàn giao config diff, bảng route và lỗi còn mở cho INT-53/INT-54; nếu auth chưa chạy, ghi blocked ở AC tương ứng thay vì kết luận route hỏng.

### 3. API

| Nhóm | Route đang có / yêu cầu khi hoàn thiện |
| --- | --- |
| Identity | `/api/auth/**`, `/api/users/**`, `/api/schedules/**` → `lb://IDENTITY-SERVICE`; giữ method/query/body và cookie theo auth contract |
| Catalog | `/api/stores/**`, `/api/catalog/**`, `/api/media/**` → `lb://CATALOG-STORE-SERVICE`; kiểm tra riêng media delete nội bộ, không suy ra mọi method đều public |
| Order | `/api/cart/**`, `/api/orders/**`, `/api/party-orders/**`, `/api/refund-requests/**` → `lb://CART-ORDER-SERVICE` |
| Nhóm còn lại | Ghi đầy đủ predicate, service ID, route ID và owner từ config đang có; đối chiếu audit `/api/audit-logs` với BE-43 |
| Prefix | Config hiện chưa khai báo rewrite ở các route trên; giữ nguyên `/api/...` nếu controller dùng cùng prefix. Chỉ thêm StripPrefix/RewritePath khi hai owner xác nhận |
| CORS | Origin FE được cho phép rõ ràng; preflight hợp lệ, credentials/cookie theo contract; không dùng origin wildcard để vượt lỗi |
| Lỗi | Giữ error shape đã công bố; phân biệt 401/403 với lỗi route/upstream; có correlation ID để truy vết, không trả stack trace/secret |

### 4. Tiêu chí hoàn thành

- Catalog service đăng ký Eureka; gọi GET sản phẩm qua Gateway với query hợp lệ: Đúng Catalog service, query không mất, không cần FE biết cổng service
- Gửi request Orders theo API spec bằng phiên hợp lệ: Đúng Cart/Order service; method/body không đổi; quyền và scope vẫn được backend kiểm tra
- Service đích không có instance sẵn sàng: Lỗi có kiểm soát theo contract, không route nhầm service hoặc treo vô hạn
- Origin FE hợp lệ thực hiện preflight và request có credentials; so sánh origin ngoài allowlist: Origin hợp lệ hoạt động theo policy, origin không cho phép không được cấp quyền CORS
- Gọi internal path và media-delete nội bộ từ cửa công khai: Không thể vượt ranh giới nội bộ bằng token khách hàng; lưu response làm evidence
- Đối chiếu request hai frontend và cấu hình bootstrap: Chỉ gọi Gateway; runtime route/config lấy từ Config Server, không nhân bản local
- Login Identity rồi gọi public/protected route qua Gateway bằng role hợp lệ: Đúng route, protected nhận actor/store từ token và public vẫn truy cập theo allowlist
- Token thiếu/sai/hết hạn: Không tới nghiệp vụ thành công
- Client giả X-Role/store header: Không nâng quyền
- Endpoint public: Không bị vô tình bắt đăng nhập
- Token sai/hết hạn/thu hồi hoặc client thêm X-Role=ADMIN: Không nâng quyền hoặc thành công nghiệp vụ, error không lộ token/secret
- Refresh/logout bằng cookie theo docs và request internal từ browser: Transport auth đúng contract; internal vẫn bị chặn, không blanket permitAll
- Gọi list/detail Catalog theo store qua Gateway và instance đã đăng ký: Đúng controller, query/storeId giữ nguyên, correlation/cache headers theo contract
- Instance Catalog thay đổi: Gateway vẫn resolve đúng registry
- Store filter: Không mất trong proxy
- Catalog unavailable: Lỗi rõ, không mock response
- Thay instance Catalog mà FE config không đổi: Gateway resolve registry, không cần FE biết host/cổng business service
- Catalog unavailable hoặc A/B cache khác availability: Lỗi rõ không mock, response không dùng lẫn cache quán
- Bàn giao contract, mã lỗi và kết quả tự kiểm thử kèm commit, môi trường, bằng chứng; ghi rõ lỗi hoặc phần còn bị chặn.

### 5. Điểm cần chốt

- *PIC Gateway + owner service:** prefix và method thật, các đường dẫn nội bộ không được publish. Quyền “authenticated” chưa đủ chứng minh endpoint chỉ dành cho service an toàn.
- *PIC Gateway + FE:** origin của từng môi trường, URL server-side/container, cookie/CORS. Chưa có domain production thì chỉ bàn giao mẫu cấu hình, không tự suy đoán.
- *INT-53:** phân công xử lý token/session/401/403; giữ middleware hiện có, không vô hiệu hóa auth để làm AC route pass.
- *BE-43:** audit route đã xuất hiện trong config nhưng phải đối chiếu contract/read permission; việc xuất hiện không chứng minh audit tích hợp xong.
