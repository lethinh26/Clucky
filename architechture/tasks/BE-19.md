## BE-19 — Tạo, khóa nhân viên, gán cửa hàng cho Admin và xếp ca cho Manager đúng phạm vi quản lý

**Phụ trách:** Trần Nguyễn Hữu Khánh · **Sprint:** 3 · **Ước lượng:** 5 SP
**Phụ thuộc:** BE-01, BE-09

### 1. User Story

- **Là Admin**, tôi muốn tạo, khóa nhân viên, gán cửa hàng cho Admin và xếp ca cho Manager đúng phạm vi quản lý để quản lý dữ liệu và thao tác nghiệp vụ đúng quyền.

### 2. Công việc

- Create Staff, lock/unlock, assign-store, xem/xếp ca theo quyền
- Nối Users UI và handoff audit/session, không chỉ ẩn nút
- Không invitation/email hoặc password chung tự đặt; không mở GET users toàn hệ thống cho Manager
- Lập bảng actor→endpoint→target role/store với API/RBAC
- Chốt cấp mật khẩu ban đầu, route list Staff của Manager và rule ca
- Triển khai validation/transaction/ownership; cập nhật phiên theo BE-17
- Nối UI và bàn giao audit mutation có đủ identity

### 3. API

| API | Quyền / yêu cầu |
| --- | --- |
| `GET /api/users` | ADM |
| `POST /api/users/staff` | ADM/MGR; PUT assign-store ADM; lock/unlock theo RBAC |

- /api/schedules theo API và quyết định quyền đã chốt; Manager scope backend
- Store reference qua contract/discovery; audit actor lấy từ backend, không FK xuyên DB

### 4. Tiêu chí hoàn thành

- Admin tạo Staff với quán hợp lệ: Một tài khoản đúng role/store; không lộ password/hash trong response
- Manager tạo/khóa Staff quán mình rồi thử target quán khác: Allow đúng scope, deny ngoài scope không side effect
- Manager/Staff gọi assign-store: Bị chặn; chỉ Admin được đổi quán
- Body role ADMIN hoặc storeId giả khi tạo Staff: Không tự nâng role/scope
- Email trùng/invalid hoặc quán không tồn tại: Lỗi đúng, không user nửa vời
- Admin đổi quán trong khi user giữ phiên cũ: Scope mới áp dụng theo revoke policy; phiên cũ không truy cập trái quán
- Khóa user đang hoạt động rồi gọi API: Từ chối theo auth/revocation contract, không chỉ chặn login mới
- Manager xem/xếp ca hợp lệ cho Staff quán mình: Lịch persisted đúng ngày/giờ và nhân sự
- Ca trùng, giao ngày, target Staff khóa hoặc quán khác: Theo policy đã chốt, lỗi không ghi lịch nửa vời
- Staff gọi POST schedule hoặc list ngoài phạm vi: Bị chặn; GET hợp lệ vẫn dùng được
- Gửi lặp create/lock hoặc hai thay đổi đồng thời: Không nhân user hoặc ghi đè quyền âm thầm; conflict được giải thích
- Catalog/session/audit handoff lỗi: Không báo sai thành công; mutation committed có audit durable, rollback không có audit thành công
- UI save lỗi rồi reload, đổi bộ lọc/locale: Giữ form, refetch server, không dùng local row làm bằng chứng
- Manager tạo Staff/xếp ca quán A rồi đọc report; thử assign-store và report B: Luồng được phép hoạt động; assign-store Admin-only và report B bị chặn, không sửa quyền để demo
- Bàn giao contract, mã lỗi và kết quả tự kiểm thử kèm commit, môi trường, bằng chứng; ghi rõ lỗi hoặc phần còn bị chặn.

### 5. Điểm cần chốt

- Owner nhân sự chốt password cấp ban đầu/đổi lần đầu, không thêm flow invite
- API schedules ADM và route list Staff MGR còn khác mô tả RBAC: chốt trước nghiệm thu, không tự mở quyền
- Chốt ca chồng/giao ngày/timezone, Staff bị khóa/gán quán khác ảnh hưởng lịch và phiên ra sao
