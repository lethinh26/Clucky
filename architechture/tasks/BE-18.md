## BE-18 — Xem, sửa hồ sơ và quản lý sổ địa chỉ, bảo đảm mỗi khách chỉ có một địa chỉ mặc định

**Phụ trách:** Trần Nguyễn Hữu Khánh · **Sprint:** 3 · **Ước lượng:** 3 SP
**Phụ thuộc:** BE-01, BE-09

### 1. User Story

- **Là khách hàng**, tôi muốn xem, sửa hồ sơ và quản lý sổ địa chỉ, bảo đảm mỗi khách chỉ có một địa chỉ mặc định để thực hiện thao tác và nhận kết quả chính xác từ hệ thống.

### 2. Công việc

- Profile allowlist, validation và address CRUD/default
- Nối form account hiện có theo contract, readback server sau lưu
- Không upload avatar BE-77 backlog, không tự cho đổi role/emailVerified hoặc chính sách xác minh email
- Chốt field cho sửa, address ID và semantics partial/full update
- Dùng repository owner-scoped và transaction/constraint cho default
- Nối validation/lưu/reload của form; giữ dữ liệu khi lỗi
- Kiểm hai user, hai request default và xóa default

### 3. API

| API | Quyền / yêu cầu |
| --- | --- |
| `GET/PUT /api/users/me` | Theo contract đã chốt |
| `GET/POST/PUT/DELETE /api/users/me/addresses` | theo API |

- Actor lấy từ phiên đã xác thực; owner address không lấy từ body
- Mọi mutation trả DTO/error chung; schema Identity riêng, không cross-service SQL

### 4. Tiêu chí hoàn thành

- User đọc/sửa field hồ sơ được phép: Lưu/readback đúng user, không đổi field khác
- Gửi role, storeId, emailVerified hoặc owner giả: Bị từ chối/loại field theo contract, không nâng quyền
- Customer tạo, sửa, liệt kê và xóa địa chỉ của mình: Danh sách/chi tiết khớp server, không còn record đã xóa
- User B dùng address ID của A ở mọi mutation/read: Không đọc/ghi được, không rò dữ liệu trong lỗi/count
- Field required trống, chuỗi vượt giới hạn hoặc ID sai: Lỗi validation cụ thể, không lưu một phần
- Hai request đặt default trên hai địa chỉ cùng user: Tối đa một default ở trạng thái commit; outcome xác định theo contract
- Xóa default hoặc xóa địa chỉ cuối: Theo policy đã duyệt; không dangling default hoặc chọn ngầm trái policy
- Hai user chọn default cùng lúc: Không ảnh hưởng lẫn nhau
- Request save timeout/DB lỗi: Không báo saved giả; UI giữ form, reload cho biết trạng thái thực
- Token hết hạn, revoke hoặc đổi user khi request đang chạy: Đúng lifecycle auth; không hiển thị địa chỉ user trước
- Chuỗi nội dung có markup và đổi vi/en: Hiển thị như dữ liệu, không thực thi script; validation không mất form
- Danh sách rỗng hoặc record vừa bị xóa trước edit: Empty/not-found rõ, không dựng địa chỉ demo
- Bàn giao contract, mã lỗi và kết quả tự kiểm thử kèm commit, môi trường, bằng chứng; ghi rõ lỗi hoặc phần còn bị chặn.

### 5. Điểm cần chốt

- Owner Identity/product chốt email/phone thay đổi có xác minh lại không
- Địa chỉ đầu tiên hoặc xóa default chọn thay thế thế nào cần policy; invariant là tối đa một default, không tự bịa địa chỉ thay thế
