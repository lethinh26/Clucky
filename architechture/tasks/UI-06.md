## 1. Làm xong task này thì dùng được gì?

Dev có PostgreSQL, Redis và Kafka local với địa chỉ kết nối rõ cho app chạy trên host hoặc container; biết dependency đã sẵn sàng và dừng/chạy lại mà không vô tình xóa dữ liệu. Deliverable chính là Compose hiện có cùng hướng dẫn vận hành an toàn, không phải thêm một stack song song.

Không bao gồm triển khai production, HA Kafka hoặc xác nhận business E2E. `healthy` chỉ phản ánh healthcheck đã định nghĩa, không bảo đảm mọi migration/consumer/nghiệp vụ hoàn tất.

## 2. Bắt đầu từ đâu? Các chỗ cần đối chiếu

Đối chiếu source ngày **05/11/2026**, không khởi động Docker:

- File thực tế là `docker-compose.yml` ở root. Đã có PostgreSQL/Redis/Kafka, network và named volumes; không tạo thêm Compose dưới thư mục khác chỉ vì layout mô tả `infrastructure`.
- Redis đã mount `redis-data:/data` và dùng `redis-cli ping`; cần xác nhận chế độ persistence hiện hành trước khi cam kết ghi nào cũng sống qua restart.
- Kafka dùng `apache/kafka:3.9.0`, KRaft single node; external advertised address là `localhost:9092`, internal là `kafka:29092`.
- Mapping `${KAFKA_PORT:-9092}:9092` không tự cập nhật advertised address khi đổi port. Đây là điểm cần xử lý/ghi giới hạn rõ, không chỉ thấy container healthy là xong.
- Kafka mount `kafka-data:/tmp/kraft-combined-logs`; phải đối chiếu effective log directory với mount trước khi kết luận dữ liệu broker persistent.
- Compose còn chứa Config/Discovery/Gateway. Build context của Config Server đang là `./backend/config-server`; Dockerfile dùng Gradle root cần được owner đối chiếu. Một số healthcheck dùng `wget`, phải xác nhận runtime image có công cụ đó khi nghiệm thu.

## 3. Contract môi trường cần ghi lại

| Thành phần | Bàn giao tối thiểu |
|---|---|
| PostgreSQL | Image/version hiện có, host port/container port, database/user lấy từ env, đường mount data và probe readiness; mỗi service vẫn sở hữu schema/database riêng |
| Redis | Địa chỉ host/container, auth nếu cấu hình, probe, named volume và mức persistence đã chọn; không cam kết durability chỉ từ PING |
| Kafka | Bootstrap host/container, advertised listeners khớp, port controller riêng, single-node replication settings, log directory và volume |
| Network | Service DNS dùng trong container; `localhost` trong app container không đại diện broker/DB ở container khác |
| Lifecycle | Lệnh chỉ khởi động infra, xem trạng thái/log, dừng rồi chạy lại; giải thích khác biệt stop/down với thao tác xóa volume |
| Env | Placeholder và default local có chủ đích; secrets đọc từ môi trường, không ghi password thật vào hướng dẫn/evidence |

## 4. Thứ tự hoàn thiện

1. Lập bảng từ Compose hiện có: service, image, env, port, network, volume, healthcheck, dependency. Chỉ điều chỉnh phần infra thuộc task này.
2. Đối chiếu PostgreSQL data directory và init mechanism; ghi rõ script khởi tạo chỉ chạy khi nào, không giả định sửa script sẽ cập nhật volume cũ. Migration nghiệp vụ vẫn thuộc Flyway của service.
3. Chốt Redis persistence với owner backend; nếu cần thay cấu hình, mô tả mức dữ liệu giữ được và shutdown an toàn, không hứa vượt semantics đã chọn.
4. Rà Kafka listener cho hai ngữ cảnh host/container. Đổi port phải đồng bộ metadata advertised; đối chiếu log directory thực với named volume, không sửa bằng xóa volume.
5. Kiểm tra nội dung probe và lệnh có sẵn trong image qua tài liệu/source được owner cung cấp; ghi timeout/retries/start period phù hợp thay vì sleep cố định.
6. Viết runbook infra-only và thứ tự phần ứng dụng: infra → Config → Eureka → services → Gateway → FE. Ghi riêng gap build context/healthcheck của app cho owner, không tuyên bố cả stack chạy được.
7. Chuẩn bị dữ liệu kiểm chứng biệt lập cho persistence/connectivity để người dùng chạy sau; chỉ dẫn khôi phục nếu cổng bận, thiếu env hoặc volume cũ không tương thích. Không chạy lệnh trong lần viết detail.

## 5. Điểm cần chốt

- **PIC infra + người dùng máy dev:** port thực, tài nguyên Docker và volume hiện hữu. Nếu port bận, chọn cấu hình được đồng ý; không tự dừng process/container ngoài project.
- **PIC infra + owner Redis/Kafka consumer:** yêu cầu persistence local, bootstrap address và broker metadata; không tự mở rộng thành production durability/HA.
- **PIC Config/Discovery:** build context và tool healthcheck trong runtime image. Chưa giải quyết thì hướng dẫn infra độc lập vẫn bàn giao được, phần boot cả stack ghi chưa xác nhận.
- Không dùng `down -v`, prune hay xóa data directory như bước sửa lỗi mặc định. Mọi reset dữ liệu cần được người dùng đồng ý riêng, nêu đúng dữ liệu sẽ mất.
