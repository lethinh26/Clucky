## BE-21 — Quản lý cửa hàng, danh mục, món, combo và tùy chọn, kiểm tra quyền và lưu dữ liệu nhất quán

**Phụ trách:** Nguyễn Duy Quang Nhật · **Sprint:** 2 · **Ước lượng:** 8 SP
**Phụ thuộc:** BE-02, BE-09, BE-10

### 1. User Story

- **Là Admin**, tôi muốn quản lý cửa hàng, danh mục, món, combo và tùy chọn, kiểm tra quyền và lưu dữ liệu nhất quán để quản lý dữ liệu và thao tác nghiệp vụ đúng quyền.

### 2. Công việc

- CRUD store/category/product/combo/options/toppings và operation store theo API
- Nối Admin form, validation/readback, handoff media/cache/audit
- Không cấp Manager quyền sửa giá/món gốc; upload thuộc BE-72, inventory BE-22
- Đối chiếu controller/service/DTO và form đang có
- Chốt ràng buộc delete, giờ mở, giá và semantics collection theo API cập nhật
- Triển khai transaction aggregate và ownership của ID con
- Nối save/refetch, cache/audit rồi kiểm CRUD từ Admin tới menu công khai

### 3. API

- Route /api/stores và /api/catalog theo API; DTO riêng cho resource và mutation
- Option choice đã lưu giữ opt-<id>, topping top-<id>; ID mới null/bỏ hoặc new-<uuid>; bỏ trường giữ collection, [] yêu cầu xóa
- ID con phải thuộc product, không lặp payload; option đang được combo tham chiếu trả 409 RESOURCE_CONFLICT khi xóa
- Audit ý định durable và invalidation sau commit, không update schema service khác

### 4. Tiêu chí hoàn thành

- Admin tạo store/category/product/combo rồi đọc lại: DTO/readback đúng, public thấy dữ liệu được phép
- Manager đổi operation quán mình và thử quán khác: Cho phép đúng scope; quán khác không đổi
- Manager/Staff sửa catalog gốc: Bị chặn cả API, không chỉ ẩn UI
- Update giữ ID options/toppings cũ: Không tạo ID mới hoặc mất tham chiếu combo
- Bỏ options/toppings so với gửi []: Bỏ giữ nguyên; [] xóa có kiểm tra tham chiếu
- ID con của product khác hoặc ID lặp payload: Reject toàn transaction, không sửa một phần
- Xóa option đang được combo tham chiếu: 409 RESOURCE_CONFLICT, combo/product giữ nguyên
- Combo có thành phần invalid, giá/required field lỗi: Không ghi aggregate nửa vời
- Hai form cùng sửa hoặc retry save: Không mất dữ liệu âm thầm theo concurrency contract
- DB rollback khi save, cache/audit đang hoạt động: Không publish thành công hoặc invalidate thành trạng thái giả; commit có handoff truy vết
- Upload ảnh lỗi khi chỉnh form: Theo BE-72, không báo saved ảnh hoặc mất field catalog
- Delete resource còn được dùng và giờ qua nửa đêm: Theo policy đã chốt, không sửa hóa đơn cũ
- Admin tạo store/product, voucher STORE A rồi Customer browse/preview tại A/B: Public readback đúng resource, discount chỉ đúng eligibility/quán, invalid save không dữ liệu nửa vời
- Bàn giao contract, mã lỗi và kết quả tự kiểm thử kèm commit, môi trường, bằng chứng; ghi rõ lỗi hoặc phần còn bị chặn.

### 5. Điểm cần chốt

- Owner Catalog chốt delete/archive các resource đang được tham chiếu, không sửa snapshot Order
- Chốt giá âm/0, giờ giao ngày và trạng thái quán nếu docs chưa xác định; tách rule đã chốt option khỏi câu hỏi cũ
