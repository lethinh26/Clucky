# [BE-76] Google OAuth qua Firebase: migration `firebase_uid`, Firebase Admin verify ID token, `POST /api/auth/google` + `/google/complete` 

**Loại:** Task
**Sprint:** Sprint 2 — Backend
**Story Point (SP):** 7
**PIC:** M4 
**Deliverable:** ``POST /api/auth/google`, `/google/complete`, `identity-db` migration `

## Mô tả

Thực hiện **Google OAuth qua Firebase: migration `firebase_uid`, Firebase Admin verify ID token, `POST /api/auth/google` + `/google/complete` ** xuyên suốt phần được giao, đúng domain và contract của Clucky. Cross-domain vào `identity-service` — phối hợp với M1 theo contract, không sửa code của M1 ngoài phần hook cần thiết.

## Phạm vi

- Đối chiếu SRS/API/database docs.
- Migration mới (không sửa Flyway V1): `users` thêm `firebase_uid` unique nullable; `password_hash` + `phone` chuyển nullable.
- Firebase Admin SDK verify ID token: chữ ký + `aud` + `iss` + `email_verified`. Không dùng Firebase làm user store — PostgreSQL là source of truth.
- `POST /api/auth/google` {idToken}:
  - `firebase_uid` đã link → trả JWT.
  - Email đã tồn tại nhưng chưa link → link `firebase_uid`, trả JWT.
  - Chưa có user → tạo `pendingToken` (Redis TTL 10 phút, chứa uid+email+name+avatar) → trả `{status: "REQUIRES_PASSWORD", pendingToken}`.
- `POST /api/auth/google/complete` {pendingToken, password} → tạo CUSTOMER ACTIVE (bỏ OTP vì Google đã verify email), hash BCrypt → trả JWT.
- `POST /api/auth/register` với email đã tồn tại (kể cả tài khoản Google) → `EMAIL_EXISTS` 409.
- Giữ Config Server, Eureka, Gateway, database/schema riêng, RBAC/storeId.
- Mail Sender nằm trong Notification Service, Gmail SMTP App Password từ env/Config Server.
- Cloudinary là external media provider; không lưu binary trong PostgreSQL, không lộ `CLOUDINARY_API_SECRET`.

## Acceptance Criteria

1. Deliverable tồn tại đúng vị trí và build không lỗi.
2. Luồng chính hoạt động: user mới → REQUIRES_PASSWORD → complete → JWT; user cũ → JWT thẳng.
3. ID token giả/hết hạn/email chưa verify → 401; `pendingToken` hết hạn → 410.
4. `POST /api/auth/register` trùng email tài khoản Google → 409 `EMAIL_EXISTS`.
5. `firebase_uid` unique; không cross-service DB join, secret hard-code hoặc frontend gọi thẳng service.
6. Có evidence kiểm tra thực tế.
7. Nếu media: validate MIME/size, lưu `secure_url` + `public_id`, cleanup sau commit và không lộ secret.
8. Nếu mail: Gmail SMTP STARTTLS, retry hữu hạn, email_logs, không rollback nghiệp vụ khi gửi lỗi.

## Ghi chú kỹ thuật

- Firebase config: `FIREBASE_ENABLED`, `FIREBASE_SERVICE_ACCOUNT_JSON` (hoặc `FIREBASE_APPLICATION_CREDENTIALS`), `FIREBASE_PROJECT_ID`.
- `pendingToken` lưu Redis `auth:google:pending:{token}` TTL 10 phút; một lần dùng, xóa sau complete.
- Cloudinary config: `CLOUDINARY_ENABLED`, `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`, `CLOUDINARY_FOLDER`.
- Gmail config: `MAIL_SENDER_ENABLED`, `MAIL_SENDER_USERNAME`, `MAIL_SENDER_APP_PASSWORD`.
