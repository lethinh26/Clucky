## BE-76 — Đăng nhập Google qua Firebase, xác minh ID token, yêu cầu tài khoản mới hoàn tất mật khẩu và phát JWT Clucky

**Phụ trách:** Lê Phú Thịnh · **Sprint:** 2 · **Ước lượng:** 8 SP
**Phụ thuộc:** BE-01, BE-09, BE-17, BE-12

### 1. User Story

- **Là khách hàng**, tôi muốn đăng nhập Google qua Firebase, xác minh ID token, yêu cầu tài khoản mới hoàn tất mật khẩu và phát JWT Clucky để thực hiện thao tác và nhận kết quả chính xác từ hệ thống.

### 2. Công việc

- Verify Firebase, link existing verified email, one-time pending/complete-password, migration và Google UI flow theo API 05/11
- Session/cookie/CSRF hiện hành theo Browser_Sessions.md 08/11, reuse BE-17
- Không Google login cho nhân sự, không user password null, không tự fetch avatar Google hoặc auto-link email chưa verify
- Đối chiếu GoogleAuthService/verifier/pending/session và runbook config, không giả provider bật
- Giữ link/complete atomic, unique normalized email/uid và recovery DB/Redis
- Nối popup trên Login/Register, validation/expiry/retry và cookie bootstrap
- Kiểm email-first/Google-first, race/conflict/unknown response và cùng session auth lifecycle

### 3. API

| API | Quyền / yêu cầu |

### 4. Tiêu chí hoàn thành

- Google mới rồi complete password hợp lệ: Trước complete không user/phiên; sau đó một Customer cùng cookie chuẩn
- Google lại user đã hoàn tất: Cùng user, không hỏi đặt mật khẩu lần nữa
- Google-first login bằng email/password sau logout: Password đã đặt hoạt động, sai password bị chặn
- Email-first verified rồi Google: Link cùng account, không đổi password/userId/hồ sơ/đơn/điểm
- Email register trùng Google hoặc UID/email xung đột: 409 đúng code, không ghi đè account/password
- Email chưa verify, LOCKED, non-Customer: Từ chối theo contract, không auto-link nâng quyền
- Token sai project/provider/expiry/revoked/unsigned: Reject, không cấp phiên hoặc tạo pending hợp lệ
- Pending hết hạn/dùng lại hoặc hai complete đồng thời: GETDEL một lần, tối đa một user, reject replay
- DB rollback sau consume pending hoặc commit mất response: Bắt đầu Google lại an toàn; đã commit thì login user cũ, không reset password
- Password boundary ký tự/byte/complexity và input quá dài: Validation giống register theo API, không truncation
- Firebase disabled/Redis/provider lỗi hoặc rate-limit: 503/429 đúng, không mock success hoặc bypass verify
- Popup bị hủy, form close, vi/en, mobile/keyboard: Loading kết thúc, pending không lưu lâu/localStorage, retry hướng dẫn rõ
- Refresh/logout/reload và guest cart sau Google: Cookie/session/Origin theo BE-17, merge lỗi giữ giỏ, response user cũ bị bỏ
- Reset password Google-first: Email dùng mật khẩu mới, Google cùng account; revoke phiên theo contract
- Bàn giao contract, mã lỗi và kết quả tự kiểm thử kèm commit, môi trường, bằng chứng; ghi rõ lỗi hoặc phần còn bị chặn.

### 5. Điểm cần chốt

- Firebase project/credential/authorized domains và mailbox test cần owner xác nhận; không xin private key qua task
- Transport/pending/password đã chốt ở API, không mở lại thành lựa chọn body-token hoặc nullable password
- Chốt migration xử lý dữ liệu legacy bất thường bằng kế hoạch, không overwrite credential thắng race
