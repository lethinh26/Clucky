## 3. Contract cấu hình và tài liệu

- `/v3/api-docs` là JSON OpenAPI, `/swagger-ui.html` là entry UI theo tài liệu API; các asset UI cần được phục vụ khi bật. Chỉ là đường dẫn yêu cầu kiểm tra, chưa xác nhận URL môi trường đã hoạt động.
- Tên service/version rõ ràng; bearerAuth có scheme bearer và format JWT. Ví dụ dùng placeholder, không nhúng token, email thật, mật khẩu hoặc key.
- Schema ApiError có timestamp/status/error/code/message/path; PageResponse và DTO phản ánh JSON thật, không lộ JPA entity/hash/token internals.
- Phân trang page zero-based, size/sort và validation phải mô tả đúng endpoint đã có. Không thêm query parameter tưởng tượng cho endpoint chưa implement.
- Global bearerAuth hiện có phải được override đúng cho operation public khi triển khai controller: route công khai không bị tài liệu ghi là bắt buộc token; route bảo vệ không bị bỏ requirement.
- Docs chỉ mô tả giới hạn quyền, không thực thi RBAC. Try it out vẫn phải chịu security của API; docsEnabled không cấp quyền quản trị.

## 4. Thứ tự thực hiện

1. Liệt kê service có springdoc/config, endpoint đã có mapping và endpoint chỉ được nêu trong spec. Phân biệt rõ API thật với backlog; không tạo controller rỗng để làm docs trông đầy đủ.
2. Đối chiếu OpenApiConfig/DTO/error schema từng service; dùng springdoc/annotation hiện có thay vì viết JSON OpenAPI thủ công trùng source.
3. Đối chiếu bearer requirement của operation công khai/bảo vệ với API/RBAC và filter chain. Ghi ví dụ 400/401/403/404 theo BE-10, không trả một generic 200 cho mọi lỗi.
4. Giữ config runtime ở Config Server. Kiểm tra flag và allowlist cùng bật/tắt; không permitAll toàn bộ API hoặc actuator để mở Swagger.
5. Chốt URL docs nội bộ ở mục 5 rồi cấu hình server URL phù hợp. Frontend vẫn gọi Gateway; URL docs nội bộ không phải lý do để frontend gọi business service trực tiếp.
6. Người phụ trách tự mở docs/đọc JSON khi được phép và ghi evidence theo mục 7; không gọi mutation nghiệp vụ thật qua Try it out khi chỉ nghiệm thu docs.
