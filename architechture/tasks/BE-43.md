## BE-43 — Audit Service độc lập, sở hữu bảng audit_logs và cung cấp API tra cứu nhật ký quản trị theo quyền

**Phụ trách:** Mai Sơn Việt · **Sprint:** 2 · **Ước lượng:** 5 SP
**Phụ thuộc:** UI-03, UI-06, BE-09, BE-10

### 1. User Story

- **Là người phát triển**, tôi muốn audit Service độc lập, sở hữu bảng audit_logs và cung cấp API tra cứu nhật ký quản trị theo quyền để triển khai và tích hợp đúng dữ liệu, quyền và contract của hệ thống.

### 2. Công việc

- Base service, Config/Eureka/Gateway, schema duy nhất audit_service.audit_logs, migration và API đọc
- Filtering/pagination/DTO/allowlist, dữ liệu lịch sử cần kế hoạch chuyển nếu có
- KAFKA-10 ghi producer/consumer; không triển khai retention/delete job hoặc lưu audit sang Review Report
- Đối chiếu Audit module/schema/route thực tế, không tạo service thứ hai
- Chốt DTO/allowlist và migration lịch sử an toàn
- Triển khai query scope/index/paging và config bootstrap
- Kiểm Admin/Manager negative, payload canary và nguồn consumer handoff

### 3. API

| API | Quyền / yêu cầu |
| --- | --- |
| `GET /api/audit-logs` | MGR/ADM; filter actorId/actorRole/sourceService/action/targetType/targetId/storeId/from/to |

- ADM mọi role theo quyền; MGR chỉ thao tác STAFF của quán mình, scope áp trước count/page
- EventId/correlation/source/actor/store/target/time và sanitized before/after theo contract, không entity/rawpayload

### 4. Tiêu chí hoàn thành

- Admin tra cứu mọi role và filter hợp lệ: Kết quả/pagination/count đúng
- Manager quán A xem thao tác STAFF A: Cho phép đúng subset
- Manager yêu cầu role MGR/ADM hoặc store B/all: Không mở rộng tập quyền kể cả OR/filter tamper
- Customer/Staff gọi API hoặc frontend thử POST/PUT/DELETE audit: Deny/không route mutation theo contract
- Invalid IDs/date range/page/size: Lỗi validation, không exception thô
- Timestamp boundary và sort bằng nhiều record cùng thời điểm: Paging deterministic theo contract, không trộn scope
- Payload before/after chứa token/password/OTP: DTO/mapper loại secret nhưng giữ field an toàn cần giải thích
- Module khởi động với Config/Eureka/Gateway khi người dùng kiểm: Độc lập đúng source config/route, thiếu config lỗi rõ
- Consumer chưa ghi dữ liệu thật: Empty hoặc blocked integration, không coi seed là đã audit toàn hệ thống
- Migration dữ liệu cũ/duplicate eventId: Có plan/reconcile/rollback, không reset DB để né
- Schema/service khác cố ghi audit trực tiếp: Không thiết kế FK/join/write xuyên service; API đọc cùng bảng consumer sở hữu
- Bàn giao contract, mã lỗi và kết quả tự kiểm thử kèm commit, môi trường, bằng chứng; ghi rõ lỗi hoặc phần còn bị chặn.

### 5. Điểm cần chốt

- Owner dữ liệu chốt audit cũ ở đâu, eventId legacy và migration/rollback; không xóa trước đối chiếu
- Chốt retention/query limits nếu chưa có yêu cầu; chưa chốt không tự thêm xóa dữ liệu
- Mở allowlist action-specific với KAFKA-10, không giả generic map đủ mọi domain
